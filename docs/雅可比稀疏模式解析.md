# Pinocchio 雅可比稀疏模式解析：`supports` → `extended_support` → `span_indexes_vector` / `sparsity_pattern_vector`

> 本文专讲 Pinocchio 里表达"关节雅可比哪些列非零"的一套变量：它们**是同一信息的不同形态**，串成一条从"树拓扑"到"雅可比列稀疏性"的数据流。搞懂它，就懂了 Pinocchio 为何能把稠密 $O(n^2)$ 的雅可比/约束计算降到与树深成正比。

## 1. 一图看懂四者关系

它们是**同一信息的四种形态**，一条数据流串起来：

```
      树拓扑                     展开到列               物化存储（两种等价形式）
 ┌──────────────┐   按 idx_v/nv   ┌──────────────────┐   ┌────────────────────────────┐
 │ supports[j]  │───────────────▶│ extended_support │──▶│ span_indexes_vector[j]     │ 索引列表
 │ = 关节 id 路径│    展开每个关节   │ = 速度列索引列表  │   ├────────────────────────────┤
 └──────────────┘                └──────────────────┘   │ sparsity_pattern_vector[j] │ 布尔掩码
   (持久字段)                       (addJoint 临时变量)      └────────────────────────────┘
                                                              (持久字段, 供算法用)
```

- **`supports[j]`**：根→关节 $j$ 路径上的**关节 id**（持久，树拓扑）。
- **`extended_support`**：把这条路径**展开成速度列索引**（`addJoint` 里的**临时变量**）。
- **`span_indexes_vector[j]`**：`extended_support` 的**本体存储**（非零列索引列表）。
- **`sparsity_pattern_vector[j]`**：同一信息的**布尔掩码**形式（长度 nv）。

$$\underbrace{\texttt{supports}[j]}_{\text{关节 id 路径}}\ \xrightarrow{\ \text{按 idx\_v/nv 展开}\ }\ \underbrace{\texttt{extended\_support}}_{\text{列索引}}\ \Longrightarrow\ \begin{cases}\texttt{span\_indexes\_vector}[j]\ (\text{索引列表})\\[2pt]\texttt{sparsity\_pattern\_vector}[j]\ (\text{布尔掩码})\end{cases}$$

## 2. 四个变量各是什么

| 变量 | 类型 | 是什么 | 寿命 |
|------|------|--------|------|
| `supports[j]` | `std::vector<JointIndex>` | 根→$j$ 路径上的**关节 id**（首元=universe(0)，末元=$j$） | Model 持久字段 |
| `extended_support` | `std::vector<Eigen::Index>` | 该路径展开成的**速度列索引**（`idx_v` 那套） | `addJoint` 局部临时变量 |
| `span_indexes_vector[j]` | `std::vector<Eigen::Index>` | 关节 $j$ 雅可比的**非零列索引列表** | Model 持久字段 |
| `sparsity_pattern_vector[j]` | `BooleanVector`（长度 nv） | 关节 $j$ 雅可比的**非零列布尔掩码** | Model 持久字段 |

**语义统一**：它们都在回答同一个问题——"**关节 $j$ 的雅可比 $J_j\in\mathbb{R}^{6\times n_v}$，哪些列可能非零？**"只是 `supports` 用关节粒度、后三者用列粒度；`span_indexes` 用稀疏列表、`sparsity_pattern` 用稠密掩码。

---

## 3. 关键概念：三个不同的"空间"

理解三者区别的钥匙是分清**关节 id 空间**与**速度列空间**：

| | `supports[j]` | `extended_support` / `span_indexes_vector[j]` |
|---|---|---|
| **元素含义** | **关节 id**（0..njoints-1） | **速度列索引**（0..nv-1，即 `idx_v` 那套） |
| **住在哪个空间** | 关节 id 空间 | 速度自由度 / 雅可比列空间 |
| **长度** | 路径上的**关节个数** | 那些关节的 **nv 之和**（= 非零列数） |
| **含 universe?** | 含（首元恒为 0） | **不含**（universe nv=0，展开无贡献） |
| **含自己?** | 含（末元恒为 $j$） | 含（末尾单独补上自己的 v 段） |

**为什么长度不同**：一个关节可能占**多列**。浮动基（FreeFlyer）一个关节就占 6 列，球副占 3 列。所以"路径上 4 个关节"展开后可能是"8 个列索引"——这正是 `supports`（关节粒度）→ `extended_support`（列粒度）的**放大**。

---

## 4. `sparsity_pattern_vector` 的行与列

`sparsity_pattern_vector` 是 `std::vector<BooleanVector>`，概念上一个 **`njoints × nv` 布尔矩阵**：

- **外层索引（行）= 关节 id** $i$：`sparsity_pattern_vector[i]` 是关节 $i$ 的掩码。
- **内层索引（列）= `nv` 个速度自由度** $k$，即雅可比 $J_i$ 的**第 $k$ 列**。

$$\texttt{sparsity\_pattern\_vector}[i][k]=\texttt{true}\iff \text{DoF }k\in\texttt{supports}[i]\iff J_i\text{ 第 }k\text{ 列可能非零}$$

> **它不是 6×nv 的行列**：稀疏性按**整列**记——若 DoF $k$ 不在 $i$ 的支撑路径上，$J_i$ 第 $k$ 列的**全部 6 个空间行都为 0**，故记一个 `false`。twist 的 6 维被"压掉"，不细分到分量。

| | 列 $k=0$ … 列 $k=n_v-1$（速度自由度） |
|---|---|
| **行 $i=0$（universe）** | 全 false |
| **行 $i$（关节 i）** | 支撑路径上的列为 true，其余 false |

## 5. 构建过程：`addJoint` 阶段⑨逐行

三者在 `addJoint`（[model.hxx](../include/pinocchio/src/multibody/model.hxx)）追加关节时一次性建好。核心两步：

**① 先把已有关节的掩码扩容补零**（因新关节让全局 nv 变大）：

```cpp
if (joint_nq > 0 && joint_nv > 0)
  for (auto & sparsity : sparsity_pattern_vector) {
    const Eigen::Index old_size = sparsity.size();
    sparsity.conservativeResize(nv);          // 拉长到新 nv，保留原有元素
    sparsity.tail(nv - old_size).setZero();   // 新增尾部补 false（conservativeResize 不初始化！）
  }
```

> 新增的列属于**新关节**（后代/旁支，绝非任何老关节的祖先），所以对老关节恒为零 → 补 `false`。`setZero` 不能省，因 `conservativeResize` 的新元素是未初始化垃圾。

**② 由 `supports` 展开出新关节的 `extended_support`，再存成两种形式**：

```cpp
EigenIndexVector extended_support;
const auto & jsupport = supports[joint_id];               // [0(universe), 祖先..., 自己]
for (size_t j = 1; j < jsupport.size() - 1; ++j) {        // 遍历真祖先（跳过 universe 与自己）
  const JointIndex a = jsupport[j];
  for (int k = 0; k < nvs[a]; ++k)
    extended_support.push_back(idx_vs[a] + k);            // ★ 把祖先 a 展开成 [idx_v, idx_v+nv) 列
}
for (int k = 0; k < joint_nv; ++k)
  extended_support.push_back(joint_idx_v + k);            // 末尾补上自己的 v 段

BooleanVector sparsity_pattern = BooleanVector::Zero(nv);
for (auto col_id : extended_support) sparsity_pattern[col_id] = true;

sparsity_pattern_vector.push_back(std::move(sparsity_pattern));  // 布尔掩码版
span_indexes_vector.push_back(std::move(extended_support));      // 索引列表版（extended_support 本体）
```

注意最后一行：**`extended_support` 被 move 进 `span_indexes_vector[joint_id]`**——所以 `span_indexes_vector[j]` 就是那个临时变量的归宿。

## 6. 完整实例：一步步算出三者

取树 `universe(0) → FreeFlyer(1) → RX(2) → RX(3)`，另有一支 `RX(2) → RX(4)`：

```
        0(universe)
        │
        FreeFlyer(1)
        │
        RX(2) ───────┐
        │            │
        RX(3)        RX(4)
```

**列布局**（`idx_v`/`nv`）：FreeFlyer 占列 0–5（nv=6），RX(2)=列6，RX(3)=列7，RX(4)=列8。全局 `nv=9`。

### 关节 3 的三者

**① `supports[3]`（关节 id 路径）**：根到 3 = `0 → 1 → 2 → 3`

$$\texttt{supports}[3]=[\,0,\ 1,\ 2,\ 3\,]\quad(\text{4 个关节 id})$$

**② `extended_support`（展开成列）**：遍历真祖先 {1,2}，补自己 {3}

| 关节 | idx_v | nv | 展开出的列 |
|------|-------|----|-----------|
| 1 (FreeFlyer) | 0 | 6 | 0,1,2,3,4,5 |
| 2 (RX) | 6 | 1 | 6 |
| 3 (自己) | 7 | 1 | 7 |

$$\texttt{extended\_support}=[\,0,1,2,3,4,5,\ 6,\ 7\,]\quad(\text{8 个列索引})$$

**对比鲜明**：`supports[3]` 只有 **4 个关节 id**，`extended_support` 却有 **8 个列索引**——浮动基一个关节展开成 6 列。

**③ 两种存储形式**：

$$\texttt{span\_indexes\_vector}[3]=[\,0,1,2,3,4,5,6,7\,]$$

$$\texttt{sparsity\_pattern\_vector}[3]=[\underbrace{T,T,T,T,T,T}_{\text{FF }0-5},\ \underbrace{T}_{6},\ \underbrace{T}_{7},\ \underbrace{F}_{8}]$$

第 8 列（RX(4)）为 `false`——因为关节 4 在**另一支**，动它不影响关节 3。

### 关节 4 的三者（另一支）

- `supports[4]=[0,1,2,4]`
- `extended_support = [0,1,2,3,4,5, 6, 8]`（FF 的 6 列 + RX2 的列6 + 自己列8）
- `sparsity_pattern_vector[4] = [T,T,T,T,T,T, T, F, T]`——第 7 列（RX(3)）为 `false`。

**关节 3 与 4 互不影响**：它们的掩码在对方那列都是 `false`，体现了分叉树的稀疏结构。

## 7. 使用示例：约束雅可比只算非零列

最典型的消费者是**约束/接触动力学**。以点接触约束（[point-constraint-model-base.hxx:456](../include/pinocchio/src/constraints/point-constraint-model-base.hxx#L456)）为例——两个连杆 `joint1`/`joint2` 间的接触雅可比：

```cpp
auto & s1 = model.sparsity_pattern_vector[joint1_id];   // 两个接触关节的列掩码
auto & s2 = model.sparsity_pattern_vector[joint2_id];
for (Eigen::Index jj = 0; jj < model.nv; ++jj) {
  if (s1[jj] || s2[jj]) {                 // ★ 该列对 joint1 或 joint2 有影响才算
    jacobian_matrix.col(jj).setZero();
    if (s1[jj]) { ...用 joint1 一侧贡献填这列... }
    if (s2[jj]) { ...用 joint2 一侧贡献填这列... }
  }
  // else：该列对两个接触关节都为零 → 跳过整列，不做任何 SE3/叉乘
}
```

**效果**：人形 `nv=34`，右手接触只依赖右臂 ~7 个关节 → 只算 7 列、跳过 27 列，**省 ~80%**。树越深、接触越局部，省得越多。消费者还包括帧接触、关节限位/摩擦约束、约束动力学导数（`constrained-dynamics-derivatives.hxx`）。

## 8. 两种遍历风格：掩码 vs 索引列表

`span_indexes_vector` 与 `sparsity_pattern_vector` 是同一信息的两种存法，按场景选用：

| 需求 | 用哪个 | 写法 |
|------|--------|------|
| **判"某列是否非零"** | `sparsity_pattern_vector[i]`（布尔掩码） | `for jj in 0..nv: if mask[jj] {...}` |
| **只遍历非零列** | `span_indexes_vector[i]`（索引列表） | `for jj in span_indexes[i] {...}` |

- 多关节要做 `mask1[jj] || mask2[jj]`（如接触两端）时，**布尔掩码**随机访问更方便（示例 7）。
- 单关节只想跳到非零列时，**索引列表**免去逐列判断、更省。

## 9. 速查表与一句话

| 变量 | 空间 | 形式 | 含 universe | 长度 | 用途 |
|------|------|------|:---:|------|------|
| `supports[j]` | 关节 id | 列表 | ✅ | 路径关节数 | 树拓扑（雅可比稀疏、CRBA 等的源头） |
| `extended_support` | 速度列 | 临时列表 | ❌ | Σnv | 构建稀疏模式的中间产物 |
| `span_indexes_vector[j]` | 速度列 | 索引列表 | ❌ | Σnv | 遍历非零列 |
| `sparsity_pattern_vector[j]` | 速度列 | 布尔掩码 | ❌ | nv | 判某列是否非零 |

> **一句话**：`supports[j]` 是"根→j 路径上的**关节 id**"；把它按各关节的 `idx_v/nv` **展开成速度列索引**，就得到 `addJoint` 的临时变量 `extended_support`；后者原样存成 `span_indexes_vector[j]`（索引列表）、并布尔化成 `sparsity_pattern_vector[j]`（长度 nv 的掩码）。三者是"同一稀疏性"的关节级→列级→两种存储形态，让约束/雅可比算法**只碰非零列**，把 $O(n^2)$ 降到与树深成正比。
